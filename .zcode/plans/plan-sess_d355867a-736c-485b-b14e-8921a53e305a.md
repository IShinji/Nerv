# Router 迁移 Rust —— 第一个大脑模块（含过渡期衔接机制）

## Context

方向已定：Python brain（~11k 行）逐模块迁入 Rust，Python 只修 bug。`router/` 是第一个迁移目标：小（315 行）、自包含、无状态、测试全部离线可跑（LLM-free），且有 golden eval 钉住行为。本方案同时定下过渡期机制，后续模块照此办理。

**关键现状**（探索结论）：
- JSON-RPC 面只有 `route` / `heartbeat` / `ping`；`route` = pending 检查 → `router.classify`（LLM 调用）→ `orchestrator.dispatch`。唯一不变量：**pending confirm 必须在模型调用之前处理**（`ipc.py:88-92`）。
- `route` 的调用方有两个：gateway（`core/gateway/src/main.rs:136`）和 GUI（`gui/src-tauri/src/main.rs:103`），都走 `shared::brain_client`。
- Router 行为链：空消息短路 → LLM 调用（provider 前缀分发：`claude-cli:` 子进程 + 重试分类、`local:` Ollama HTTP、`litellm:` 云）→ JSON 解析（含正则兜底提取）→ sanitize（agent 别名表、中英问候白名单、问句抑制）→ 全部异常时关键词 fallback。golden eval 6 例钉住解析+sanitize。
- Rust 侧尚无 HTTP 客户端；Rust 测试惯例是 `/bin/sh` 假子进程脚本（brain_client.rs 已用同款技巧模拟 fake brain，可直接复用来模拟 fake `claude` CLI）。

## 设计决策：过渡期衔接机制（写入 CLAUDE.md）

**按职责拆协议，宿主侧分流**。`route` 一个方法拆成三步，由新的 Rust brain crate 提供统一 facade，gateway 和 GUI 都调它：

1. `check_pending`（RPC→Python，无模型调用）：命中 `confirm <id>`/`cancel <id>` → 直接回复，行为与今天完全一致
2. **Rust Router 本地 classify**（不再跨进程）
3. `execute`（RPC→Python）：Python orchestrator.dispatch，返回 `RouteResult.model_dump()` + `reply` 覆写——**线上协议形状不变**，gateway 的 `format_brain_response` 无需改动

好处：pending-先于-模型调用的不变量保持；orchestrator 留在 Python 不动；`brain_client` 的重试/超时/重启逻辑原样作用于 `check_pending`/`execute`；gateway 与 GUI 不重复分流逻辑。此模式记入 CLAUDE.md，作为后续模块（memory、tools…）迁移的模板。

**新 crate**：`core/brain/`（crate 名 `nerv-brain`，加入 core workspace）。这是未来整个 Rust 大脑的家，第一个模块是 `router`。gateway 和 GUI 依赖它；facade `nerv_brain::BrainHandle::reply(...)` 包装 `BrainClient`。

## 实施步骤（两个 PR）

### PR 1：`nerv-brain` crate + Router 纯增量移植（不改任何现有行为）

新文件（均在 `core/brain/src/`）：
- `router/mod.rs`：`RouteResult`（serde，7 字段带默认值，与 `brain/nerv/models.py:6-26` 一致）；`Router::classify(message)`；`parse_response` → `extract_json`（正则 `\{[^}]+\}` 兜底）→ `sanitize_route_result`（别名表、`DIRECT_REPLY_EXACT_MESSAGES`、`QUESTION_MARKERS` 逐条照搬）；`fallback_classify`（四组关键词表照搬）；常量 `ROUTER_TIMEOUT=60s`
- `llm/mod.rs`：provider 前缀分发的种子版（这是迁移第 2 步 `llm/` 的起点）：
  - `claude-cli:` —— `tokio::process::Command` 跑 `claude -p --model <alias> --output-format json`，json_mode 时追加 "Respond with ONLY a single valid JSON object"；移植重试语义（默认 2 次、`classify_failure` 分类、指数退避）
  - `local:` —— reqwest（`default-features = false, features = ["json"]`，仅 localhost 无需 TLS，新依赖在 PR 里说明理由）调 Ollama `/api/chat`，`format: "json"`
  - `litellm:` / 裸名 —— 返回 unsupported 错误 → Router 捕获走关键词 fallback（与后端故障同路径，符合双层错误模型；config 默认是 claude-cli，litellm 处于 reserved 状态）
- `handle.rs`：`BrainHandle` facade（check_pending → classify → execute 三步）
- `prompts/router.system.md` + `prompts/router.user.template.txt`：prompt 文本从 `brain/nerv/router/prompt.py` **逐字节拷贝**成数据文件，运行时读取（遵守"prompt 是数据文件"规则）

移植的测试（全部离线，`#[cfg(test)]`，沿用现仓库测试风格）：
- `test_router.py` 三组测试 → Rust：fallback 关键词映射、解析三态（合法 JSON / 夹杂文本 / 垃圾输入→fallback）、sanitize（别名归一、"现在几点"抑制回复、"你好"保留回复）、RouteResult 默认值与序列化
- golden eval 6 例（`eval.py` 的 `GOLDEN_ROUTING`）→ `#[test] golden_routing_pipeline_is_fully_correct`
- claude-cli 重试语义（fake `claude` 用 `/bin/sh` 脚本，同 brain_client 测试手法）：可重试 vs 致命错误、退避
- live eval 作为 `#[ignore]` 测试保留手动入口

**开发期 parity 验证**（删 Python 前）：用 golden 6 例 + 若干额外中英文消息，跑 Python 旧链路（parse+sanitize）与 Rust 新链路并排 diff 输出一致后才动 PR 2。

### PR 2：切换协议 + 删除 Python router

- `core/brain/src/handle.rs` 完成 facade 接线；`core/gateway/src/main.rs`：`brain.call("route", …)` → `handle.reply(...)`；`gui/src-tauri/src/main.rs` send_message 同样切换；gateway 不再注入 `NERV_ROUTER_MODEL`（Python 不再读），保留 `NERV_MODEL_TIER0..3`、`NERV_OLLAMA_URL`（orchestrator 的 agent 完成仍走 Python llm client）
- `brain/nerv/ipc.py`：`route` handler 换成 `check_pending` + `execute`（复用现成的 `dispatch_pending_command` / `orchestrator.dispatch`，响应形状不变）
- **删除 Python 侧**：`nerv/router/`、`nerv/eval.py`、`nerv/models.py`（RouteResult 只有 router 用）、`get_router_model`（config.py 死代码）、`tests/test_router.py`、`tests/test_eval_routing.py`；更新 `tests/test_ipc.py`（route 用例改为 execute/check_pending，沿用现有 mock 手法）
- 文档：CLAUDE.md 加"过渡期迁移机制"小节 + 标记 router 已迁移；README 状态表更新（Rust brain: router ✅）
